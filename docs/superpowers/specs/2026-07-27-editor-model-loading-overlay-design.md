# 编辑器模型加载遮罩设计

## 目标

模型通过拖拽或点击加入场景时，在模型资源完成下载、解析和 Three.js 实例化前，为中央三维画布提供明确的加载反馈，避免用户误以为操作没有生效。

## 范围

- 覆盖素材面板拖拽模型到画布的入口。
- 覆盖点击素材添加模型的入口。
- 不覆盖几何体、灯光等本地同步创建操作。
- 不改变模型加载、场景命令、选择和错误提示的现有行为。

## 交互设计

模型添加操作开始后，中央三维画布上方显示全尺寸遮罩、HUD spinner 和“模型加载中...”文案。遮罩只覆盖画布区域，顶部工具栏、素材面板和属性面板保持原有布局。

spinner 使用 `https://loading.io/assets/mod/spinner/hud/index.svg` 指定的视觉资源。资源作为编辑器本地静态文件随项目发布，页面不在运行时请求第三方站点，避免离线环境、跨域限制或第三方不可用导致 loading 缺失。

遮罩使用 `role="status"` 和 `aria-live="polite"` 暴露加载状态，spinner 图片本身作为装饰隐藏于辅助技术。

## 状态与数据流

`EditorWorkspace` 负责模型添加操作及 loading 状态：

1. 拖拽或点击模型调用统一的异步添加包装函数。
2. 包装函数在调用 `commands.addAssetNode()` 前增加待处理计数。
3. `commands.addAssetNode()` 继续等待 `EditorCanvas.applyNodeAdded()`，因此 Promise 完成表示模型已实例化并进入画布。
4. 操作在 `finally` 中减少待处理计数。
5. 待处理计数大于零时，`EditorCanvas` 显示加载遮罩；归零后关闭。

使用计数器而不是布尔值，以支持用户连续添加多个模型。任一模型先完成时不会提前隐藏仍在加载的其他模型。

## 组件边界

`EditorWorkspace`：管理模型添加生命周期，复用同一个函数处理拖拽和点击入口，并将布尔 loading 属性传给画布。

`EditorCanvas`：只负责根据属性渲染画布内遮罩，不理解命令、资源或并发语义。

本次不向 Three Engine 增加资源事件。当前命令 Promise 已准确覆盖模型实例化周期，扩展引擎公共 API 会增加不必要的影响范围。

## 错误处理

模型添加失败时，`finally` 必须关闭对应 loading 计数；现有 `ElMessage.error` 继续显示错误原因。loading 不替代错误提示，也不吞掉异常。

组件卸载后不需要额外取消模型请求；现有 Engine 释放逻辑负责处理失效加载。响应式状态随工作区销毁。

## 样式约束

- 遮罩绝对定位于 `.editor-canvas` 内并覆盖整个画布。
- 使用半透明深色背景，保留场景轮廓但明确阻止画布交互。
- spinner 使用稳定宽高，避免资源加载或文案变化引发布局偏移。
- 文案使用紧凑的编辑器字号，不遮挡相邻面板。
- 遮罩层级高于画布统计和场景交互状态。

## 验收与测试

组件测试覆盖：

- 拖拽模型后立即显示指定 loading。
- 点击模型后显示相同 loading。
- 模型添加成功后关闭 loading。
- 模型添加失败后关闭 loading，并调用现有错误提示。
- 两个并发模型操作中，第一个完成后 loading 仍显示，全部完成后关闭。
- 拖拽几何体或灯光不会显示模型 loading。

执行编辑器相关 Vitest、TypeScript 检查和构建。运行开发环境后，在浏览器中验证遮罩范围、spinner 渲染以及成功和失败状态均无重叠或残留。
