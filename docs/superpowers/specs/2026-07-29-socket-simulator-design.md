# Socket 模拟服务设计

## 1. 目标

新增独立工作区应用 `apps/socket-server`，为场景预览和发布运行时提供可直接连接的 WebSocket 数据源。第一版不接第三方设备，使用自动轨迹和 HTTP 接口生成模拟数据，补齐“模拟数据 → WebSocket 服务 → 画布 Socket 任务 → 场景动作”的运行链路。

## 2. 范围

第一版包含：

- 在 `ws://127.0.0.1:18080` 接受画布运行时连接。
- 通过 HTTP 接口广播单条或批量 Socket 任务消息。
- 启动和停止一个 `device-position` 自动轨迹模拟器。
- 查询服务健康状态、模拟器状态和当前客户端数量。
- 接受并忽略画布发送的 JSON 心跳消息 `{"type":"ping"}`。
- 纳入仓库现有统一启动、停止和地址提示脚本。
- 提供协议、集成和生命周期自动化测试。

第一版不包含：

- 第三方设备、MQTT、消息队列或数据库接入。
- 用户、令牌、权限和公网安全能力。
- 浏览器控制台或可视化管理页面。
- 修改运行时已有的 Socket 任务执行能力。
- 补齐文本、图表组件的可视化消费逻辑。

## 3. 架构选择

采用独立应用 `apps/socket-server`，不把 WebSocket 功能并入 `apps/api-server`。

原因：

- 保持画布当前默认地址 `ws://127.0.0.1:18080` 不变。
- 模拟器故障、重启和快速迭代不影响项目、场景和资源 API。
- 后续接入真实数据时可以替换消息生产端，而不需要修改画布协议。
- 避免触碰当前 `apps/api-server` 中用户尚未提交的修改。

HTTP 与 WebSocket 共用一个 Node HTTP Server 和同一个端口。普通 HTTP 请求进入控制 API；WebSocket Upgrade 请求由 `ws` 接管。

## 4. 组件边界

### 4.1 消息协议

协议模块负责校验和规范化手动消息及自动模拟消息，不负责网络传输。

合法消息结构：

```json
{
  "taskCode": "device-position",
  "taskType": "ModelPosition",
  "taskTime": 800,
  "taskData": {
    "x": 1,
    "y": 0,
    "z": 2
  }
}
```

字段规则：

- `taskCode`：必填非空字符串。
- `taskType`：可选；存在时必须属于场景 Schema 当前支持的十种 Socket 任务类型。
- `taskTime`：可选非负整数，单位毫秒。
- `taskData`：可选 JSON 对象。
- HTTP 广播接口接受单个消息对象或消息数组。
- 服务不重写合法消息字段，广播载荷与校验后的输入保持一致。

### 4.2 客户端注册表与广播器

注册表只保存处于 WebSocket `OPEN` 状态的客户端。连接建立和关闭时更新数量。广播器把每条消息分别序列化并发送给所有可用客户端，返回实际发送次数；批量输入保持原始顺序。

客户端上行消息不作为任务转发。对于画布定时发送的 `{"type":"ping"}`，服务接受并忽略，不回复业务 JSON，避免画布把 `pong` 误诊断为缺少 `taskCode` 的任务消息。其他上行消息同样不广播，只记录可诊断日志。

### 4.3 自动模拟器

模拟器维护唯一一个定时器。`start()` 和 `stop()` 都是幂等操作，重复启动不会创建多个循环。

每个时间步生成：

```json
{
  "taskCode": "device-position",
  "taskType": "ModelPosition",
  "taskTime": 800,
  "taskData": {
    "x": 0,
    "y": 0,
    "z": 0
  }
}
```

其中 X/Z 使用连续角度在水平面形成圆形轨迹，Y 恒为 0。默认间隔 1000 ms、轨迹半径 5；两者可由环境变量覆盖。模拟器默认不自动启动，防止项目启动后在用户未准备任务映射时持续产生诊断；调用启动接口后才开始广播。

### 4.4 HTTP 控制 API

所有响应使用 JSON。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/health` | 返回 `status`、`clientCount`、`demoRunning` 和运行配置摘要 |
| `POST` | `/api/messages` | 校验并广播单条或批量消息，返回 `acceptedCount` 和 `deliveryCount` |
| `POST` | `/api/demo/start` | 幂等启动自动模拟，返回当前状态 |
| `POST` | `/api/demo/stop` | 幂等停止自动模拟，返回当前状态 |

HTTP JSON 请求体最大 1 MiB。格式错误、超过大小或协议校验失败返回 `400`；未知路由返回 `404`；内部异常返回 `500`，同时保留服务端诊断信息但不把堆栈暴露给调用方。开发接口允许跨域调用，支持 `OPTIONS` 预检。

### 4.5 进程与配置

默认配置：

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `SOCKET_HOST` | `127.0.0.1` | 监听地址 |
| `SOCKET_PORT` | `18080` | HTTP 与 WebSocket 端口 |
| `SOCKET_DEMO_INTERVAL_MS` | `1000` | 自动消息间隔 |
| `SOCKET_DEMO_RADIUS` | `5` | 圆形轨迹半径 |

环境变量必须在启动阶段校验。端口必须为 1 到 65535 的整数，间隔必须为正整数，半径必须为有限非负数；无效配置使进程以非零退出码终止。

进程响应 `SIGINT` 和 `SIGTERM`：先停止模拟器，再关闭 WebSocket 客户端和 HTTP Server，最后退出。服务使用 Node 24、TypeScript、`ws`、Zod 和 Vitest，与仓库现有技术栈保持一致。

## 5. 数据流

### 5.1 手动消息

1. 调用方向 `POST /api/messages` 提交 JSON。
2. HTTP 层完成大小限制和 JSON 解析。
3. 协议模块校验单条或批量任务消息。
4. 广播器按顺序向所有已连接画布客户端发送消息。
5. 接口返回接收消息数与实际投递次数。
6. 画布按 `dataSourceId + taskCode` 命中任务并执行模型动作。

### 5.2 自动消息

1. 调用 `POST /api/demo/start`。
2. 自动模拟器立即生成第一条位置消息，之后按间隔持续生成。
3. 每条消息走与手动消息相同的广播器。
4. 调用 `POST /api/demo/stop` 或关闭进程后停止。

## 6. 画布配置约定

验证自动模拟时，场景必须存在：

- 已启用的数据源，URL 为 `ws://127.0.0.1:18080`，允许自动连接。
- Socket 任务 `taskCode` 为 `device-position`。
- 任务类型为 `ModelPosition`。
- 目标节点为需要移动的模型节点。

服务只负责推送消息，不持有项目、场景或节点 ID，也不修改画布配置。目标节点始终由场景里的任务映射决定。

## 7. 测试策略

单元测试覆盖：

- 合法单条和批量消息解析。
- 缺少 `taskCode`、非法 `taskType`、负数或小数 `taskTime`、非对象 `taskData` 被拒绝。
- 环境变量默认值和非法配置。
- 自动轨迹数据有限、Y 为 0、半径符合配置。
- 模拟器启动和停止幂等。

集成测试使用操作系统分配的随机端口，覆盖：

- WebSocket 连接和断开反映到健康状态。
- HTTP 单条广播能被一个和多个客户端收到。
- 批量消息保持顺序。
- 无效 HTTP 输入返回 `400` 且不广播。
- 自动模拟启动后产生消息，停止后不再产生。
- 客户端心跳不会被广播或触发业务回复。
- 关闭服务后释放端口和定时器。

仓库级验证包含该应用的单测、类型检查、构建，以及现有受影响脚本的静态检查。最后执行一次真实进程冒烟测试：启动服务、连接 WebSocket 测试客户端、调用广播接口、确认收到消息、再优雅停止。

## 8. 项目集成与文档

- 新应用提供 `dev`、`build`、`start`、`test` 和 `typecheck` scripts，因此会被 pnpm workspace 命令发现。
- `scripts/start-lan.ps1` 启动 Socket 服务并写入独立日志。
- `scripts/start-all.ps1` 把 `18080` 纳入端口检查与健康检查，并显示本地和局域网 Socket 地址。
- `scripts/stop-all.ps1` 能识别并停止该项目的 Socket 服务进程。
- `.env.example` 记录全部 Socket 环境变量。
- `README.md` 增加启动、画布任务映射、自动模拟和手动 `curl` 示例。

局域网运行时，服务使用 `SOCKET_HOST=0.0.0.0`，画布数据源 URL 使用启动信息中展示的 `ws://<LAN-IP>:18080`，不能让远端浏览器继续连接它自己的 `127.0.0.1`。

## 9. 验收标准

- 执行统一启动脚本后，`GET http://127.0.0.1:18080/health` 返回健康状态。
- 配置正确的画布预览能够连接 `ws://127.0.0.1:18080`。
- 启动自动模拟后，映射到 `device-position` 的模型沿轨迹持续移动。
- 手动广播位置、旋转、颜色、显隐等合法消息时，画布按已有任务配置执行。
- 无效消息不会广播，并返回可定位的校验错误。
- 关闭项目后端口 `18080` 被释放，不残留自动模拟定时器或项目 Node 进程。
