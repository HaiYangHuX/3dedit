# 相机漫游源站一致性重构设计

日期：2026-07-29

## 背景

当前编辑器已具备漫游路径绘制和播放能力，但与 ThreeFlowX 4.0.4 线上编辑器存在明显差异：

- 当前取点会射线吸附到业务模型的朝上表面，而源站始终将鼠标射线投影到世界 `Y=0` 平面。点击模型时，当前实现因吸附到模型表面而显得水平/高度位置偏移。
- 当前实现会丢弃超过最大距离的点，源站会沿射线截断到最大距离，不会出现点击无响应。
- 当前路径仅有统一标记和单层虚线，缺少源站的起点/终点颜色语义、方向箭头、三层轨迹及悬停预览。
- 路径数据没有速度字段，播放系统硬编码使用 `4` 单位/秒。
- 面板缺少源站已有的速度输入和点位坐标编辑。

## 参考基线

实现对照以下两个权威来源为准：

1. 线上站点 `http://threeflowx.cn/edit/#/`，页面标识版本 `4.0.4`，Three.js `r183`。
2. 线上构建产物：
   - `/edit/js/renderScene-BuLmTtCj.js` 中的漫游类、取点函数和标记构造。
   - `/edit/js/index-BOzshH26.js` 中的相机漫游面板。
   - `/edit/css/index-eogtJl2C.css` 中的 `camera-roaming` / `cr-*` 样式。

Gitee 公开仓库当前分支不包含此新版漫游功能，因此以同版本线上构建产物作为源码行为基线。

## 目标

- 取点坐标、点击阈值、远距离截断和默认点位高度与源站一致。
- 完整迁移速度配置、悬停路径、点位坐标编辑、播放/停止和删除操作。
- 起点使用红色 `S`，终点使用绿色 `E`，中间点使用蓝色，并保留点位序号。
- 绘制、悬停和播放视觉层的生命周期互不污染，切换场景和销毁时完整释放 GPU 资源。
- 保留项目已有的稳定路径 ID、命令历史、显式保存和 Runtime 共用播放架构。

## 非目标

- 不实现导航网格、自动避障、曲线插值、循环播放或分段速度。
- 不复制源站 Pinia 中依赖数组下标的不稳定内部结构。
- 不将悬停、播放等瞬时 UI 状态写入 SceneDocument。

## 数据设计

`CameraRoamingPath` 增加必填字段：

```ts
speed: number; // 0.1 ~ 50，默认 4，单位/秒
```

Schema 使用 `.default(4)` 为旧场景补齐字段，无需数据库迁移。新建路径显式写入 `speed: 4`。更新速度和点位继续通过 `UpdateCameraRoamingListCommand`，因此可撤销且只在点击“保存”后持久化。

## 取点设计

1. 使用 WebGL Canvas `getBoundingClientRect()` 将 `clientX/clientY` 转换为 NDC。Canvas 在当前架构中与源站 `sceneApi.container` 同尺寸，但 `DOMRect` 还能正确处理浏览器缩放、页面滚动和 CSS 布局。
2. 从当前 Camera 发射射线，只与世界 `Y=0` 平面求交，不再检测模型表面。
3. 射线与平面无交点时，沿 Camera 朝向取 `max(abs(camera.y) * tan(fov / 2), 5)` 距离的前方点，与源站回退一致。
4. 交点距离超过 `max(camera.position.length() * 2, 50)` 时，沿射线截断到最大距离，而不是丢弃点位。
5. 投影结果先限制为 `y >= 0.5`，再增加 `0.05`，最终常规地面点为 `y=0.55`。

## Engine 设计

`CameraRoamingSystem` 分别拥有三个临时视觉组：

- `drawingVisualGroup`：当前 Ctrl/⌘ 绘制结果。
- `hoverVisualGroup`：面板卡片鼠标经过时的路径预览。
- `previewVisualGroup`：正在播放的路径。

开始绘制、开始播放、替换路径列表和销毁时按源站规则清理互斥视觉层。每个视觉组持有独立 Geometry/Material/Texture，移除时去重释放。

新增方法：

```ts
showHoverPath(path: CameraRoamingPath): boolean;
hideHoverPath(): void;
```

`EditorEngine` 对外暴露基于稳定 ID 的包装，Vue 层不持有 Three.js 对象。Runtime 仅复用速度播放，不暴露编辑器悬停功能。

## 可视化设计

颜色和尺寸使用源站常量：

- 起点：`#ff7a59` / `#ff4d6d`，标签 `S`。
- 终点：`#34d399` / `#10b981`，标签 `E`。
- 中间点：`#38bdf8` / `#0ea5e9`。
- 轨迹：蓝色光晕实线 + 蓝色虚线 + 黄色核心虚线，每段中点放置方向锥体。
- 标记：底部光圈、立柱、八面体核心、线框壳与 Sprite 序号标签。

点位角色由数组位置派生，不在 SceneDocument 内重复保存 `start/end` 字段，避免排序或删除后产生不一致。

## 面板设计

卡片按源站结构展示：序号徽标、名称、`定位图标 + N 个点位`、速度输入、编辑点位、播放/停止、删除。

- `mouseenter`：非正在播放的卡片显示悬停路径。
- `mouseleave`：清理悬停路径。
- 速度：`0.1 ~ 50`，步长 `0.5`，精度 `1`，提交时替换路径列表。
- 点位编辑：弹窗表格编辑 X/Y/Z，精度 `3`，保存时校验至少两个有限坐标。
- 添加按钮、空状态、卡片密度和深色主题一致迁移源站 `cr-*` 样式。

## 错误处理

- 速度非有限数、超出范围或小于等于零时不提交。
- 点位坐标为非有限数时阻止保存并显示 Element Plus 警告。
- 路径少于两点时不允许播放或保存编辑。
- 悬停的路径被更新/删除/切换场景时立即清理，不保留旧引用。

## 测试与验收

### 自动化

- Scene Schema：旧路径默认补齐 `speed: 4`，非法速度被拒绝。
- Three Engine：画布带偏移时中心点正确；模型高台不再影响投影；远点被截断而不是丢弃。
- Three Engine：速度 `2` 与 `4` 的分段进度不同，最短时长仍为 `400ms`。
- Three Engine：悬停、播放和绘制视觉组正确切换，起点/终点的角色和标签正确。
- Vue：卡片悬停/离开、速度更新、点位编辑、播放/停止和删除事件完整转发。
- Editor Workspace：新建路径写入默认速度，速度/点位更新进入命令历史。

### 浏览器

1. 同一画布位置在源站和本项目各取三点，对比点位与网格的相对位置。
2. 点击模型顶部时，本项目与源站一样使用地面投影。
3. 鼠标经过路径卡片时显示完整路径，离开后消失。
4. 首点红色 `S`、末点绿色 `E`、中间点蓝色，轨迹方向可辨识。
5. 修改速度后播放时长明显变化，刷新前保持未保存状态，点击保存后持久化。
6. 点位编辑弹窗可修改 X/Y/Z，保存后悬停路径和播放均使用新坐标。
