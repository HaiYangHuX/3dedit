# 相机漫游表面点位投影修复设计

日期：2026-07-22

## 背景与根因

相机漫游当前把画布点击射线固定投影到世界 `Y=0` 平面，再把点位保存为 `Y=0.55`。画布矩形与 NDC 的换算本身正确，但当用户点击楼层、高台或模型顶部时，点位仍会落到底层地面，因此在三维视图中表现为明显错位或进入模型内部。

现有播放逻辑还会忽略路径点自身的 `Y`，统一把相机放在世界 `Y=2`。如果只修复添加点位，高台路径在播放时仍会下降到模型内部，所以点位投影与播放高度需要一并修复。

## 目标

- 点击可见业务模型的朝上表面时，把漫游点位放在该表面上方。
- 点击空白区域或不适合作为行走面的表面时，保持现有世界 `Y=0` 地面回退行为。
- 不命中编辑器 Gizmo、网格、选择框、测量线、漫游标记等辅助对象。
- 保持已有地面路径的数据与播放效果兼容，不引入数据迁移。
- 通过单元测试和 Codex 内置浏览器中的真实交互验证修复。

## 非目标

- 不实现导航网格、碰撞避障、坡度寻路或路径自动绕障。
- 不修改漫游路径 Schema，也不迁移历史场景数据。
- 不改变添加点位的 Ctrl/Command 点击交互、连线样式、移动速度或转向动画。

## 方案选择

采用“仅检测业务文档根节点下的模型表面”方案。

不对整个 `Scene` 做无差别检测，因为场景中包含 TransformControls、选择框、网格、测量线和漫游标记，容易产生错误命中。也不继续使用固定高度平面，因为固定平面无法表达多楼层和高台。

`EditorEngine` 向 `CameraRoamingSystem` 传入一个按需返回当前 `SceneDocumentSystem.root` 的回调。漫游系统早于场景文档创建，而且切换资源解析器时文档系统会被替换，因此不能在构造时保存固定根节点引用。运行时仍复用同一漫游系统；表面根节点解析回调作为可选能力，不影响只负责播放的调用方和现有测试注入点。

## 点位投影数据流

1. 使用画布 `getBoundingClientRect()` 把 `clientX/clientY` 转成 NDC，保持现有正确的画布偏移处理。
2. 从当前相机生成射线，并递归检测业务文档根节点下的对象。
3. 按距离从近到远检查交点，只接受同时满足以下条件的交点：
   - 命中对象及其祖先链均处于可见状态；
   - 命中对象不是编辑器辅助对象；
   - 交点具有面法线；
   - 面法线经过对象世界法线矩阵变换后，`normal.y >= 0.5`。
4. 找到合格交点后，保存 `surfacePoint + (0, 0.55, 0)`，即路径点代表表面上方 0.55 米的标记位置。
5. 没有合格交点时，使用原有世界 `Y=0` 平面求交，并保存 `Y=0.55`。
6. 若射线与回退平面平行、交点位于射线后方或超过现有最大距离限制，则不添加点位。

`normal.y >= 0.5` 对应最大约 60° 的坡面。墙面和底面不会吸附点位，而缓坡、楼板和模型顶部可以作为表面。

## 数据兼容与播放高度

路径点格式继续为 `[x, y, z]`，不增加字段。

- 旧地面路径的点位高度为 `0.55`。
- 新地面路径仍保存为 `0.55`。
- 表面高度为 `surfaceY` 时，新路径保存为 `surfaceY + 0.55`。
- 播放相机高度改为 `pathPoint.y + (2 - 0.55)`，即 `pathPoint.y + 1.45`。

因此旧路径 `0.55` 仍播放在 `Y=2`；例如高台表面为 `Y=4` 时，点位保存为 `4.55`，播放相机位于 `Y=6`。水平位置、分段时长和朝向插值保持现状。

## 组件改动

### `CameraRoamingSystem`

- 在选项中接收可选的业务表面根节点解析回调，并在每次有效点击时获取当前根节点。
- 将表面交点筛选封装成独立的私有投影步骤，继续保留 `projectPoint` 注入能力，避免破坏现有交互测试。
- 复用现有 `Raycaster`，并使用法线矩阵把交点面法线转换到世界空间。
- 用命名常量表达点位离地高度 `0.55` 与相机相对点位高度 `1.45`，避免继续散落魔法数字。
- 播放时保留每个路径点的 `Y` 并增加相对眼高。

### `EditorEngine`

- 创建漫游系统时传入 `getSurfaceRoot: () => this.documentSystem?.root`，把可命中范围限制在当前业务文档模型中，并兼容首次加载及切换场景。

不需要更改 UI、Schema 或持久化接口。

## 测试设计

在 `CameraRoamingSystem.test.ts` 中保留现有交互测试，并增加不注入 `projectPoint` 的真实 Three.js 射线测试：

- 点击高台顶部，生成的路径点高度等于顶部世界高度加 `0.55`。
- 射线存在多个交点时，选择最近的合格朝上表面。
- 隐藏对象不参与命中。
- 垂直墙面或没有合格模型交点时回退到世界 `Y=0.55`。
- 旧路径点 `Y=0.55` 播放高度仍为 `Y=2`。
- 高台路径点播放时保持 `pathPoint.y + 1.45` 的相对眼高。
- 现有绘制、取消、重复点过滤、控制器恢复与资源清理测试继续通过。

必要时补充 `EditorEngine` 装配断言，确保业务根节点被传入漫游系统；优先通过行为测试覆盖，避免测试私有实现。

## 浏览器验收

使用 Codex 内置浏览器打开本地编辑器，在包含高台模型的测试场景中：

1. 在空白网格添加两点，确认标记仍与点击位置一致且位于地面上方。
2. 在高台顶部添加至少两个点，确认标记与连线位于顶部而不是底层地面。
3. 点击模型侧墙，确认不会把点位吸附到墙面。
4. 保存并播放高台路径，确认相机沿高台上方移动且不会钻入模型。
5. 播放已有地面路径，确认相机高度和移动行为没有回归。

## 风险与边界处理

- 大型模型的递归射线检测只在用户完成有效点击时触发，不进入逐帧循环；本次不引入额外空间索引。
- 非均匀缩放模型的法线必须使用法线矩阵转换，不能只应用对象四元数。
- 若模型材质只渲染正面，射线命中仍遵循 Three.js 材质侧面规则；本次不改变材质设置。
- 业务模型若被隐藏，其子对象即使自身 `visible=true` 也必须视为不可见。
